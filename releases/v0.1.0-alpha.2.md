# FRS v0.1.0 Alpha 2 — Verified Vertical Slice & SIMD Retrieval Optimization

**Pre-release for technical evaluation only — not approved for live or unsupervised attendance.**

FRS v0.1.0 Alpha 2 introduces the verified vertical slice connecting the Flutter Android kiosk, high-performance FastAPI pure ONNX vision backend, and Next.js 16 administrative console with persistent session capture queues, vectorized SIMD retrieval optimizations, and private authenticated media storage.

## What's New in Alpha 2

### 1. Pure ONNX Runtime Vision Engine & Math Fixes
- **Native ONNX Runtime Inference:** Integrated custom `SCRFDDetector` and `ArcFaceRecognizer` running official InsightFace Buffalo_L graphs (`det_10g.onnx`, `w600k_r50.onnx`) without requiring MSVC C++ 14.0+ Build Tools or Cython.
- **Fixed SCRFD NMS Box Distortion:** Converted bounding coordinates $[x_1, y_1, x_2, y_2] \to [x_1, y_1, w, h]$ before `cv2.dnn.NMSBoxes`, preventing false suppression of adjacent faces.
- **Affine Landmark Normalization:** Scales reference 5-point anchor coordinates proportionally to arbitrary input dimensions, ensuring sub-millimeter eye/nose/mouth alignment.

### 2. High-Performance Vectorized SIMD Retrieval
- **Burst-Level Gallery Memoization:** Decrypts and caches cohort embeddings once per burst, cutting redundant DB queries and AES-256-GCM decryptions by 66.7%.
- **SIMD BLAS Dot Product:** Replaces iterative Python comparison loops with vectorized NumPy matrix-vector multiplication ($\mathbf{s} = \text{clip}(\mathbf{G} \mathbf{q}, -1.0, 1.0)$).
- **Algorithmic Micro-Benchmark Evidence:** Reduced median burst retrieval latency from **33.39 ms** to **9.96 ms** (**3.35x speedup**) on a synthetic in-memory SQLite test workload with 100% mathematical equivalence to cosine distance (algorithmic/memory optimization; does not reflect physical camera or network latency).

### 3. Next.js 16 Modern Administrative Console
- **Biometric Enrollment Workflow (`/enrollment`):** Multi-frame student face enrollment with live camera feedback, centering/lighting checks, and real-time backend validation.
- **Review Queue (`/reviews`):** Human-in-the-loop exception management allowing administrators to review ambiguous or non-accepted capture attempts side-by-side with reference images.
- **Attendance Corrections & Manual Entries (`/attendance`):** Authorized audit-logged manual punches, punch status corrections (PRESENT, LATE, EXCUSED), and real-time filtering.
- **Audit Trail Explorer (`/audit`):** Cryptographic event inspection with authenticated, short-lived signed previews via Cloudinary.

### 4. Security Hardening & Session Policy
- **Zero Secrets in Repository:** Audited with automated secret scanners and verified clean by GitGuardian with 0 secrets detected.
- **Session-Scoped Production Attendance:** Legacy unscoped identification and verification endpoints are blocked in production (`HTTP 403 Forbidden`). All captures are strictly scoped to the active class session's enrolled students.
- **Android Network Security Config:** Hard-blocks cleartext HTTP communication over public interfaces, permitting HTTP only on local loopback.
- **AES-256-GCM Encryption at Rest:** Embeddings and in-flight capture queue payloads are encrypted at rest.

## Important Limitations & Release Blockers

- **Model Weight Licensing:** DeepInsight Buffalo_L model weights are released under a non-commercial academic research license (WebFace600K). Commercial operators must clear or substitute commercially licensed weights.
- **Empirical Calibration:** FAR/FRR thresholds must be empirically calibrated on target hardware and representative demographic populations before deployment.
- **Presentation Attack Testing:** Benchmark against physical presentation attack datasets (printed photos, 2D screens, 3D masks) before enabling unattended kiosk operations.
- **Regulatory Notice & Consent:** Operators must implement institutional compliance procedures under applicable data protection regulations (GDPR, FERPA, BIPA).
